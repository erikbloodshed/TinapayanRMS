# Syncfusion UI Framework

Part of [PLAN.md](../../PLAN.md), the project guide: how the app uses Syncfusion Essential Studio for WPF, the theme and colours built on it, the windows, the controls' quirks, the toasts and the Reports screen, as they are now. When each part came in, who asked for it and what it replaced are in the [build plan](build-plan.md)'s dated log. A section named without a file (Tech Stack, Domain Model, Application Architecture, Development Environment) is PLAN.md's.

## Packages, licence and where to look

- **Every Syncfusion package is on one version, 35.1.43, the `SyncfusionVersion` property in `Directory.Packages.props`**: `DataGridExcelExport`, `Licensing`, `SfChart`, `SfGrid`, `SfInput`, `SfNavigationDrawer`, `SfSkinManager`, `SfTextInputLayout`, `SfTreeView`, `Themes.Windows11Light` and `Tools`, each `.WPF`. The theme package requires `SfSkinManager` and `Licensing` at its own version (NuGet refuses a mismatch as a downgrade, `NU1605`), and Syncfusion doesn't support mixing versions, so they upgrade together.
  - **A patch within a release keeps the licence key; a new major release (34 to 35) needed a new one**, generated from the Syncfusion account first. The build compiles the key in (Tech Stack).
  - **At each upgrade, decompile both versions' assemblies and diff them** for what the app touches: the private members `ChromelessWindowMask` and `ChromelessWindowDpi` reach by reflection, the template parts looked up by name, and the behaviours the workarounds below cover. Checked at 35.1.43: `ChromelessWindow` hasn't changed since 35.1.37, so every `AppWindow` workaround is still needed; `TabItemExtAutomationPeer.Invoke` now selects the tab; and the `SfChart` axis label template's bindings are `Mode=OneTime` (the History tab's axis labels still follow the product picked).
- **Where to look for how a control is meant to be used**, in this order:
  1. **Syncfusion's agent skills**, all 96, in `.claude/skills/syncfusion-wpf-*`, from [github.com/syncfusion/wpf-ui-components-skills](https://github.com/syncfusion/wpf-ui-components-skills) (upstream commit `3dbf20e`). Syncfusion ships them for the cross-agent `skills` CLI, which installs to `.agents/skills`, a path Claude Code doesn't scan, so they're copied to `.claude/skills/` with CRLF endings. APM (`apm.yml`, `apm.lock.yaml`) refreshes only its cache, `apm_modules/syncfusion/wpf-ui-components-skills/skills/`, from which changed files are copied in; `skills-lock.json` holds the `skills` CLI's hashes from the first install.
  2. **Syncfusion's WPF MCP server**, `syncfusion-wpf` in `.mcp.json` ([help.syncfusion.com/wpf/mcp](https://help.syncfusion.com/wpf/mcp)): the NuGet tool `Syncfusion.WPF.MCP`, whose one tool, `search_docs`, searches the current (v35) documentation. It runs as `dotnet dnx Syncfusion.WPF.MCP --yes` (`dnx` comes with the SDK; a bare `dnx` is `dnx.cmd`, which can fail to start as an MCP command), with a Syncfusion API key, separate from the licence key, from the `SYNCFUSION_API_KEY` user environment variable, so the key never goes into the repo.
  3. **The local Sample Browser source**, `C:\Users\Public\Documents\Syncfusion\WPF\34.2.2\SampleBrowser\`, a v34 install older than the packages. Grep file contents: demo filenames often don't name the control.
  4. **The assemblies themselves**, decompiled with `ilspycmd`.
- **`syncfusion-wpf-ui-builder`** (from [github.com/syncfusion/wpf-ui-builder](https://github.com/syncfusion/wpf-ui-builder)) is installed beside the control skills, but it's an 8-stage generator for building a screen from scratch, not per-control reference. It's installed as upstream ships it, and it prescribes `INotifyPropertyChanged` and `RelayCommand` MVVM and screen conventions of its own: this project's ReactiveUI and PLAN.md's conventions win wherever they differ.

## The theme

- **Syncfusion's Windows11Light theme, from its official package**, which styles every Syncfusion control, so adopting a new one needs no theme work. The theme is used whole: a trimmed copy once lost `SfDataGrid`'s styling without a word, since `SfDataGrid.xaml` merges `ChromelessWindow.xaml` and **`SfSkinManager` swallows a dictionary that fails to load**. **When a theme edit seems to do nothing, check at runtime whether the theme's style is applied at all** (`DependencyPropertyHelper.GetValueSource` on the property: `DefaultStyle` means Syncfusion's unthemed generic style), and load the dictionary into a `ResourceDictionary` inside a try/catch to see the exception. The theme's "SfTabControl" folder is `SfChromelessWindow`'s own tab strip; the general tab control is `TabControlExt`.
- **Applying it**: `App`'s static constructor registers the licence (`SyncfusionLicenseProvider.RegisterLicense`) before anything touches a Syncfusion type, then registers the theme settings, `SfSkinManager.RegisterThemeSettings("Windows11Light", App.ThemeSettings(...))`, before the host is built. `OnStartup` calls `SfSkinManager.SetTheme(mainWindow, new Theme("Windows11Light"))` before showing the window.
  - **`App.ThemeSettings`** builds the `Windows11LightThemeSettings`: `PrimaryBackground` the palette's Sky (`LatteSkyColor`, read from the resources, so the accent and `AccentBrush` can't drift), `PrimaryForeground` Sky's Ink (`LatteSkyInkColor`), and every font size 2 above the theme's (header 18, sub-header and title 16, sub-title and body 14, alt 12). `PrimaryBackground`'s setter derives every shade from the one colour, so it recolours grid selection, the tab and drawer indicators, text box focus underlines and button hover and press. It's public so the themed tests register the same (`StaThread.RunThemed`).
  - **`SfSkinManager.ApplyThemeAsDefaultStyle` is never turned on.** It would restyle every open `Window` as a `ChromelessWindow`. So WPF's own controls (`CheckBox`, `Expander`, `ProgressBar`) keep the OS look, and the theme's resources (`{skinManager:ThemeResource ...}`, `Theme.Helper`) can't be reached from the app's XAML.
  - **A new window is themed explicitly** with its owner's theme (`SfSkinManager.SetTheme(window, SfSkinManager.GetTheme(owner))`), as Settings, the print dialog and `TextPromptWindow` are, and so is a pop-up outside the window's tree, such as a tree row's context menu: `SfSkinManager` themes only what it's given.
  - **Syncfusion controls are recoloured only through `Windows11LightThemeSettings` or their own properties, never a `Style`**, which would replace the themed template. The app's keyed styles target WPF's own elements (`Border`, `TextBlock`, `Button`, `ItemsControl`), and there's no unkeyed style, which would leak into every Syncfusion template hosting that element.
- **Size mode `Default`** (`skinManager:SfSkinManager.SizeMode="Default"` on each window). In it the theme sets no minimum height on inputs and buttons, so:
  - **Every text box and button is 24px tall**: `App`'s static constructor overrides `FrameworkElement.HeightProperty`'s default (`ControlHeight`) for `SfTextBoxExt`, `DoubleTextBox`, `IntegerTextBox`, `CurrencyTextBox`, `PercentTextBox` and `ButtonAdv`. A type default is the lowest precedence, so a `Height` in XAML still wins. `ComboBoxAdv` keeps its own 25px, and grid rows are 24px.
  - **`SfTextBoxExt` has three theme gaps**, patched in `App`: its style never sets `VerticalContentAlignment`, so a type default centres the text (`OverrideMetadata`, before any box exists); its template puts the text 10px in where the other fields have 3px of padding, so `AlignTextBoxText` (a `Loaded` class handler) gives it a left padding of -6 as a local value, since the theme sets `Padding` through the default style, which outranks a type default; and its watermark sits in a plain `ContentControl` that honours neither, so a box with a `Watermark` takes `App.xaml`'s `AlignedWatermarkTemplate` (the three list search boxes and Find).
  - **Every number box's text is right-aligned**: `AlignNumberRight`, a `Loaded` class handler on `EditorBase` (what `DoubleTextBox`, `IntegerTextBox`, `CurrencyTextBox` and `PercentTextBox` are built on), sets `TextAlignment` as a local value unless the box already has one.
  - **A grid's add row is a plain empty row**: `HideAddNewRowText`, on `AddNewRowControl`'s `Loaded`, collapses the theme's grey band and its "Click here to add new row".

## The palette and design tokens

- **The colours are Catppuccin Latte.** `Themes/Palette.xaml`, merged first into `Application.Resources`, holds all 26 Latte colours by their Catppuccin names (`LatteMauveColor`, `LatteBaseBrush` and so on), and **every token in `App.xaml` names one of them; no token carries a hex code**, except `ListBackgroundBrush` and `PrintPaperBrush`, both white (below). The History tab's chart has three line colours of its own (`Trend*Brush`, in `HistoryCard`).
- **The roles follow Catppuccin's style guide**: the page Mantle, cards Base with a Crust border, headings Text, muted text Subtext 1 (Subtext 0 is only 4.4:1 on Base), read-only values Overlay 0, the accent Sky, links Blue, success Green, warning Yellow, error Red, and the neutral info notice Mauve.
- **Latte's hues are pastels, so the palette derives steps from them**: a *Tint* (the hue at 10% over Base) for a banner or badge's background; a *Deep* shade (darkened toward black in 5% steps until it makes 4.5:1 on its Tint and on Base) for text in that hue, since only Mauve, Blue and Red reach 4.5:1 unaided, and darkening toward black keeps the hue where darkening toward Text turned Green and Yellow grey; a *Wash* (the hue at 20% over Base, `Latte<Hue>WashColor`) for the figure tiles; and for Sky alone an *Ink* (`#013245`, 4.5:1 on Sky), the theme's `PrimaryForeground`, since white on Sky is 2.8:1.
  - So a coloured pair is `<Hue>Tint`/`<Hue>Deep` (the link's is Blue's), the toasts' borders are the plain hue, and `AccentSoftBrush` is the Sky Tint. **`AccentBrush` (plain Sky) is for fills, lines and borders** (the grids' `CurrentCellBorderBrush`, the unit diagram's boxes); **accent text and glyphs use `AccentForegroundBrush`**, Sky's Deep shade, since Sky is 2.5:1 on Base.
- **The theme's own neutrals aren't Latte**: `Windows11LightThemeSettings` exposes only the primary colour and fonts, so inputs and grids keep Windows11Light's white fields and grey borders. Recolouring those would take a custom theme from Syncfusion Theme Studio. `ListBackgroundBrush` is the theme's white `ContentBackground`, for the trees the theme leaves transparent, so they match the grids; `PrintPaperBrush` is the printout's paper.
- **Every `TabControlExt` is recoloured through its own properties** (`Background`, `TabPanelBackground`, `TabItemSelectedBackground`, `TabItemHoverBackground`), since the theme's content area is white and its strip and tabs neutral greys. A strip is a step darker than what it sits over, and the selected tab is its content's colour, so tab and page read as one piece: the window's tabs (`MainWindow`, `SettingsWindow`) have a Crust strip over the Mantle page (`PageTabStripBrush`, hover `PageTabHoverBrush`), and the tabs inside a card a Mantle strip over the Base card (`CardTabStripBrush`, hover `CardTabHoverBrush`).
- **The header figures sit on coloured tiles**: in the Raw Materials, Sub-Assemblies and Products headers each figure has a rounded `FigureTileStyle` block behind its label and value, 8 apart (`FigureTileGapStyle`), in a Wash (`<Hue>TileBrush`). Full-strength hues can't take text (Text on them is 1.5–3:1); on a Wash it's 5.3–6:1. **A kind of figure keeps its colour on every screen**: Base Unit Rosewater, a cost as it stands (Current Cost, Material Cost) Peach, a cost per gram (Buffered Cost, Cost per g) Yellow, a total weight Teal, a total cost (Total Cost, Batch Cost, Set Cost) Flamingo, Base Cost Pink, Current Price Sky, Markup % Green and Last Updated Mauve. Labels on a tile are Text (`FigureTileLabelStyle`), not muted, since Subtext 1 on the Mauve Wash is 4.1:1, and so is Current Price's value (Sky's Deep makes only 4.35:1 on the Sky Wash).
- **The keyed styles** are built from the tokens: `CardStyle`, `SectionHeaderStyle`, `FieldLabelStyle`, `FormLabelStyle`, `CaptionStyle`, `PanelHeaderStyle`, `SectionDividerStyle`, `EmptyStateStyle`, `AppTitleStyle`, the figure tiles', the linked badges' (`LinkedBadgeStyle`, `LinkedBadgeLinkStyle`), the Used By tiles' (`UsedByTileStyle`, `UsedByTilesStyle`) and others. `TextBlock` has no `CharacterSpacing` in WPF (it's WinUI's); a setter for it fails the build with `MC4005`.

## Windows

- **The app's windows derive from `Controls/AppWindow`**, a `ChromelessWindow` (`MainWindow`, `SettingsWindow` and `PrintPreviewWindow`), so the title bar and its Minimize, Maximize/Restore and Close buttons are drawn in the theme. **A new chromeless window derives from `AppWindow`, never `ChromelessWindow`**, or it brings back the bugs below. `ChromelessWindow` overrides `DefaultStyleKey` only for its own type, so a subclass still gets the theme's style. `TextPromptWindow` is a plain borderless `Window` drawing its own card (the Raw Materials notes).
- **`AppWindow` sets `UseNativeChrome`, `CornerRadius` 0 and `ResizeBorderThickness` 0.** Plain chromeless mode hit-tested every point as client area and resized only from the outermost pixel of the left and right edges, and it cut 8px rounded corners out of an opaque window, which drew black. With `UseNativeChrome` the theme's `SyncfusionChromelessWindowWindows11Template` and a WPF `WindowChrome` let Windows hit-test every edge and corner, and Windows 11 draws the rounded corners, shadow and border itself.
  - The chrome's resize band is bound to `ResizeBorderThickness`, which is also the border the template paints, so the window sets that to 0 and `OnSourceInitialized` gives the `WindowChrome` a local `ResizeBorderThickness` of `SystemParameters.WindowResizeBorderThickness`. `CornerRadius` 0 stops WPF painting its own curve inside Windows'.
  - **Keeping the rounded corners**: `ChromelessWindow` keeps giving the window a square region (`UpdateWindowRegion` → `SetWindowRgn`) on `WM_SIZE`, `WM_SIZING` and `WM_EXITSIZEMOVE` and on `StateChanged`, and Windows 11 doesn't round a window with a region. `AppWindow`'s own hook (`DropWindowRegion`, added before `base.OnSourceInitialized`, so it runs after Syncfusion's) takes the region off on those messages, without a redraw, and again from a queued `BeginInvoke`, since WPF raises `StateChanged` after every hook. It also asks for rounding (`DwmSetWindowAttribute`, `DWMWA_WINDOW_CORNER_PREFERENCE` = `DWMWCP_ROUND`). A real title-bar drag is what shows the region coming back; `SetWindowPos` sends no `WM_EXITSIZEMOVE`. While maximized the region is back, trimming the overhang, which is harmless.
  - **Maximizing with the button makes the window 3px taller than the work area**, behind the taskbar: `ChromelessWindow`'s `WM_GETMINMAXINFO` adds that on purpose for the border its own template draws. Double-clicking the bar or Win+Up gives the exact work area.
  - **The hook that swallows `WM_DPICHANGED` is removed** (`Controls/ChromelessWindowDpi.LetWpfHandleDpiChanges`, from `OnSourceInitialized`): with `UseNativeChrome`, `ChromelessWindow` adds a private `WndProc` hook that marks message 736 handled and does nothing else, so WPF never rescaled a window moved between monitors. It's found by reflection, and a delegate made from it equals the one Syncfusion added, so `HwndSource.RemoveHook` takes it off. `ChromelessWindowDpiTests` sends a real `WM_DPICHANGED` to an off-screen window: one fails if Syncfusion renames the hook, the other once Syncfusion stops swallowing the message, when the workaround can go.
  - **No black frame after a restore from the taskbar.** Two causes are fixed: `ChromelessWindow`'s content mask, an `OpacityMask` over the whole root grid that only rounds the bottom corners to `CornerRadius` (0 here), is cleared and its private `rootGrid` field nulled (`Controls/ChromelessWindowMask`, from `OnApplyTemplate`; `ChromelessWindowMaskTests` fails if Syncfusion renames it or drops the mask); and while maximized the window draws in software from being minimized until 500 ms after it's back (`Controls/RestoreRendering`), since WPF's hardware surface blanked a frame on most maximized restores. That last cause wasn't found; a plain WPF window never did it.
  - At runtime the theme's style replaces `ChromelessWindow`'s own `WindowChrome` with WPF's defaults (`<WindowChrome />` in the `UseNativeChrome` trigger), so `ChromelessWindow.UpdateWindowChrome` changes nothing. Giving it the intended chrome made no difference to anything, so it's left.
- **The icon**: `Assets/Icons/tinapayan-rms-icon.ico` (16 to 256 px frames) is the UI project's `ApplicationIcon`, and `AppWindow`'s constructor sets `Icon` to a `BitmapFrame` of it, since WPF doesn't fall back to the `.exe`'s icon. The title bars keep `ShowIcon="False"`, so it shows in the taskbar and Alt+Tab only.
- **The title bar** follows the Sample Browser's main window: `ShowTitle` and `ShowIcon` off (the `Title` still names the window in the taskbar), `TitleBarHeight` 30 (the theme's 40×32 caption buttons are clipped to it, so their hover wash fills the bar), `TitleBarBackground` the card colour, no `TitleBarTemplate`. The menu toggle and heading are `LeftHeaderItemsSource`; Find, Back and Forward are `RightHeaderItemsSource`, before Minimize. Settings has no Minimize, since it's modal.
  - **Those buttons are built like the window's own caption buttons**: plain WPF `Button`s, 40×32, in the theme's `WPFGlyphButtonStyle` with `Template="{DynamicResource WPFGlyphWindowButtonTemplate}"` (the template `ChromelessWindow` gives Minimize and Maximize, found by its plain key in the theme dictionary merged into the window), and `WindowChrome.IsHitTestVisibleInChrome="True"`, without which the caption area swallows the mouse. The style is fetched as `{DynamicResource {skinManager:ThemeKey Key=WPFGlyphButtonStyle, Theme={x:Type sfTheme:Windows11LightSkinHelper}}}`: the Sample Browser's `{sfskin:ThemeResource ...}` form looks once, before `OnStartup`'s `SetTheme` has merged the theme's dictionaries, and never again. A `ButtonAdv` can't match them: its 24px minimum and opaque hover and disabled fills don't flatten. The menu toggle stays focusable, since closing the drawer returns the keyboard to it.
- **Per-monitor DPI awareness**: `app.manifest` declares `dpiAwareness` `PerMonitorV2, PerMonitor` (and the legacy `dpiAware`), so WPF renders natively at each monitor's DPI instead of Windows stretching a system-DPI bitmap. It needs no code. Bitmap assets, `HwndHost` and `RenderTargetBitmap` would need per-DPI work; the app has none. **`PrintWindow` can't show DPI blur**, since it captures the window's own surface before Windows stretches it: capture the screen. For a script driving the app, PLAN.md's Application Architecture has the DPI and capture notes, and `Process.MainWindowHandle` can pick one of the app's hidden windows (`MessageWindowClass`, `SystemResourceNotifyWindow`): find the main window by its class (`HwndWrapper[…]`) and title.

## Controls

- **The controls in use**: `SfDataGrid` and `SfTreeGrid`, `SfTreeView`, `TabControlExt`, `SfNavigationDrawer`, `ButtonAdv`, `DropDownButtonAdv`, `SplitButtonAdv`, the `SfInput` editors (`ComboBoxAdv`, `SfTextBoxExt`, `DoubleTextBox`, `IntegerTextBox`, `CurrencyTextBox`, `PercentTextBox`, `SfDatePicker`), `SfChart`, `PrintPreview` and `ChromelessWindow`. Prefer a Syncfusion control over WPF's own; WPF's `CheckBox` is used where Syncfusion has none outside its grids and ribbon. PLAN.md's Application Architecture has the grids' shared behaviours.
- **An editable `DoubleTextBox` binds `Value` with `UpdateSourceTrigger=PropertyChanged`**, so a typed value reaches the ViewModel at once: otherwise a button enabled by it stays disabled until focus leaves, and the first click after typing is lost. `Value` is registered on `DoubleTextBox` itself, so `OverrideMetadata` can't change the default; set it on each binding. A box whose shown value is rounded (Raw Materials' Buffered Cost) updates on `LostFocus` instead. A box bound to a `decimal?` takes `TargetNullValue={x:Null}` and the `DecimalValueConverter` (Development Environment, Conventions).

### Buttons

- **`ButtonAdv` icons use `IconTemplate`**, a `DataTemplate`, not `SmallIcon`/`LargeIcon`, which want an image; with none set the theme shows a placeholder glyph. The icons are Segoe Fluent Icons, falling back to Segoe MDL2 Assets (`IconFontFamily`), from the `*IconTemplate` resources in `App.xaml`: reuse one, or add a named one there.
- **`ButtonAdv.Label` defaults to "Button"**, so an icon-only one sets a real `Label` in `SizeMode="Small"`, which doesn't draw it (the list toolbars: named in `Label` and `ToolTip`, `Focusable="False"`), or is a plain `Button` in the theme's glyph style (the title bar). In Small the icon box is 16 × 16 with the 14px glyph in its top-left corner, so each toolbar button sets `IconWidth`/`IconHeight` 14 and `Padding` 3,1,3,0 to centre it.
- **`DropDownButtonAdv`** (Add Sub-Assembly, Raw Materials' New Category, Reports' Columns; in `Syncfusion.Shared.WPF` beside `ButtonAdv`):
  - **Its `Content` is the drop-down**: it's a `ContentControl`, with no `Items`.
  - **It doesn't close when something inside is clicked**: it closes only from its own `OnMouseLeftButtonUp`, for a click on the button itself. Each item's `Click` sets `IsDropDownOpen = false` (`RecipeStructureCard.xaml.cs`, `NewCategoryItem_Click`), and the command still runs from the item's binding. Reports' Columns relies on it staying open while its tick boxes are clicked.
  - **Its items are `ButtonAdv`s, flattened** (`Background="Transparent"`, `BorderThickness="0"`, which the template binds onto its border) with `HorizontalContentAlignment="Left"`, so they read as menu rows and theme with everything else; a `ListBox` would keep the OS look. The theme's hover still repaints a row, opaque `#F9F9F9` against the pop-up's `#FCFCFC`, nearly invisible; a stronger one would take a template override.
- **`SplitButtonAdv`** is the Products header's New, whose arrow offers New composite product. The Vim keys' link hints click it through its protected `OnClick` and clear `IsPressed` after (Application Architecture).

### Pickers (`ComboBoxAdv`)

- **Every picker filters its list as it's typed in.** `App`'s static constructor registers a class handler on `ComboBoxAdv`'s `Loaded` (`ApplyPickerDefaults`), which sets `IsEditable=True` and `AutoCompleteMode=Suggest` on every picker whose XAML doesn't set them; `IsEditable="False"` opts one out. It's a hook because `ComboBoxAdv` owns both properties, so `OverrideMetadata` can't change their defaults, a `Style` would replace the theme's, and a subclass risks losing the theme style, which is looked up by type. `SetCurrentValue` keeps them defaults rather than local values, so a repeat `Loaded` applies them again harmlessly.
  - **No picker sets `IsTextSearchEnabled`**: the ComboBox skill says to choose it or Suggest, not both, and Syncfusion's AutoComplete sample needs `IsEditable` for Suggest to filter. The enum pickers with no `DisplayMemberPath` are editable too.
  - **Typed text never creates a record**, since every picker's form binds only `SelectedItem` (the Category pickers' add prompt reads the text deliberately). Text that matches no item stays in the box, even over a record loaded after it, but only the box shows it: the list and what Save writes come from `SelectedItem`. That's the control's own behaviour.
  - **A picker in a panel that's collapsed when its screen loads never raises `Loaded`**, so the hook misses it. `UsageFormPanel` is a `UserControl` inside a collapsed `Border` in `RecipeStructureCard`, never measured with the screen, so its template never applies and its pickers never join the visual tree, not even once the form opens. **Such a picker spells `IsEditable="True"` and `AutoCompleteMode="Suggest"` out in XAML.** The three behaviours below are class handlers registered by type for the same reason, all from `App`'s static constructor.
- **Every such picker highlights its text's best match, and Enter or Tab picks it** (`Controls/PickerMatchHighlight`, for a single-pick picker that's editable, in Suggest mode and bound to an `ItemsSource`). On its own, Suggest only filters: nothing is highlighted until an arrow key, and Enter or Tab keeps only a name typed in full.
  - The match is the one the grids' drop-downs pick (`ScreenAwareDropDownControl`): the name typed in full, then the first starting with the text, then the first containing it. It's highlighted with the item's own `IsHighlighted`, which the theme draws, at `DispatcherPriority.Loaded` after the key-up, once the picker's `OnKeyUp` has refiltered and the rows are laid out.
  - Enter and Tab from the text box set `SelectedItem` (and the box's text) before `ComboBoxAdv`'s own `OnPreviewKeyDown` runs, since a derived type's class handlers run before `UIElement`'s, which call the `On…` overrides. A name matching nothing highlights nothing, so the Category pickers' add prompt still comes up.
  - Down and Up from the text box move on from the highlighted name; the picker's own arrow keys start from `SelectedItem`, or from the top. The handler writes the next name into the box and focuses its row, as the picker does, and swallows the key-ups up to the next key-down, since `OnKeyUp` would refilter by the full name and leave only that row.
  - Moving the mouse onto another row takes the highlight off, so only one row is ever highlighted. A `MouseEnter` raised by a list refiltering under a still cursor doesn't count.
- **Every such picker selects its whole text as the keyboard enters it, by a click or by Tab** (`Controls/PickerSelectOnEntry`, on `TextBox`, limited to an editable `ComboBoxAdv`'s `PART_Editable`). The picker's own `Part_IsEdit_GotFocus` selects it (only with a pick), then the `TextBox`'s mouse-down puts the caret where the click landed.
  - `PreviewMouseLeftButtonDown` on a box without the keyboard focuses it and marks the press handled, so the box never places the caret. A click on a box that has the keyboard places the caret, and a double-click selects a word.
  - `GotKeyboardFocus` calls `SelectAll`, whether or not the text names a pick, but only when `OldFocus` is outside the picker; the picker itself counts as outside, since `ComboBoxAdv_GotFocus` hands the keyboard on to the box. The keyboard also comes back to the box from a list row, and selecting then would have the next letter replace the text. "Inside" walks up through `FrameworkElement.Parent`, then the visual parent: the list's pop-up is no visual child of the picker, but its child's logical parent is the `Popup`.
  - `PreviewTextInput` with a pick clears `SelectedItem` first, then writes the text as the box would have taken it and marks the input handled. Otherwise a letter typed over or after a picked name was lost: `Part_IsEdit_TextChanged` clears a pick its text no longer names, and `OnSelectionChanged` empties the box unless the key was Backspace or Delete (`isBackspaceOrDeleteKeyPressed`, private).
  - Tabbing into a picker still opens its list (its `OnKeyUp` compares the text with a filter it never set), the control's own behaviour.
  - `PickerSelectOnEntryTests` cover the selection on a click or Tab, typed text that names no pick, a letter typed over a pick, and a focus change from a list row. A raised click never reaches the `TextBox`'s caret placement, so they can't show the selection being lost.
- **A picker emptied while bound to a value that can't be null shows that value again once the keyboard leaves it** (`Controls/PickerRestoresPick`, on `ComboBoxAdv`'s `LostKeyboardFocus`). Backspace or Delete clears the pick (`Part_IsEdit_PreviewKeyDown`). Bound to an enum (`EditingType`, `EditingSource`), the null can't be converted, so the binding goes into error and the ViewModel keeps its value, and another record with the same value raises no change. So the handler calls `UpdateTarget` on a null `SelectedItem` or `SelectedValue` whose binding `HasError`, once `IsKeyboardFocusWithin` is false, never while the box is typed in. A picker bound to a nullable value took the null, and stays empty. A tab closing (`CloseMode="Hide"`) takes the keyboard off its pickers, so that goes through the same handler. Covered by `PickerRestoresPickTests`.
- **An editable picker in Suggest mode combines its filter into the list's shared default view**, and takes it off only while it's loaded, so a window built per use over long-lived ViewModels takes it back off when it closes (Application Architecture, the Settings dialog).

### Number boxes and Ctrl+Z

- **Syncfusion's number boxes take Ctrl+Z and Ctrl+Y for themselves, on the way down.** `DoubleTextBox.OnPreviewKeyDown`, and `CurrencyTextBox`'s, handle both keys for their own per-character undo and set `e.Handled` on every branch, even with `IsUndoEnabled` false, so a `Window.InputBindings` Ctrl+Z would be dead in every number cell and field. **`Controls/UndoShortcuts` is a class handler on `Window`'s `PreviewKeyDown`**, registered from `App`'s static constructor: tunnelling runs from the root, so the window sees the key before the box. The screen is found by walking up from `Keyboard.FocusedElement` to the first `DataContext` that's an `IUndoScreen`, which needs no registry and leaves Settings and the prompts alone.
- **A `DoubleTextBox` never draws its text with `Foreground`**: a non-zero value uses `PositiveForeground`, and 0 uses `ZeroColor` once `ApplyZeroColor` is on (Application Architecture, "A read-only number box greys its text").

### Tab controls and UI Automation

- **A `TabControlExt`'s pages stay in the UI Automation tree once built, showing or not**, so a whole-window search for a control by name ("New", the first two Edit controls) can land on another tab's. Scope `FindFirst`/`FindAll` to the view's own root element, found by a control only that screen has, never to `AutomationElement.FromHandle(hwnd)`.
- **A `TabItemExt`'s peer has only `InvokePattern`**, no `SelectionItemPattern`, and since 35.1.43 `Invoke` selects the tab. The driver clicks a main tab's centre, found as a `TabItem` by its title. The main window's tabs can also be switched without the mouse: `Invoke` the strip's ˅ button (AutomationId `PART_MenuButton`), then the `MenuItem` named after the tab, found from the desktop root by the app's process id, since it's in a pop-up; it works with the app behind other windows, and `PrintWindow` then captures it. The in-card tab controls hide that list (`ShowTabListContextMenu="False"`) and build an inactive page only when it's first shown.

### `SfTreeView`: the three lists

- **The Products, Raw Materials and Sub-Assemblies lists are `SfTreeView`s** (`ProductListCard`, `MaterialListCard`, `SubAssemblyListCard`), built the same way, so all of this holds for each. The screens' own notes have their folders and menus.
- **A row gets an expander whenever its children are an observable collection, even an empty one**, so a leaf has no child property at all: only the folder type gets a `HierarchyPropertyDescriptor` (`ChildPropertyName="Children"`), and the tree's own `ChildPropertyName` is left unset, as Syncfusion's `SelectionDemo` does.
- **Whether a folder is open is kept on the model** (`IsExpanded`, the descriptor's `IsExpandedPropertyName`), which the tree reads and writes both ways: `AutoExpandMode` is applied only if the tree's view is built before the control has loaded.
  - **The tree doesn't read `IsExpanded` for a folder added back to its parent** (it expands the parent instead), **nor can it open a folder with nothing in it** (`TreeCollectionView.ExpandNode` sets `IsExpanded` to `ChildNodes.Any()`), and it doesn't look again when rows arrive under a folder it holds closed. So each tree's `Refresh` raises `IsExpanded` again (`AnnounceExpanded`) for each folder it re-adds, each open folder that has just got its first rows, and each open top-level folder that was empty when it began (on the screen showing at startup, the tree binds before the first load has filled it).
- **Removing the selected item from its collection drops it from the selection.** A row moved to another folder leaves one collection and joins another, so the screen puts the selection back (`SyncTreeSelection`), and `Refresh` makes every removal before any insertion, so a moved row is never in two folders at once.
- **Several rows can be picked (`SelectionMode="Extended"`), so the screens bind `SelectedItems`, not `SelectedItem`.** The tree takes the ViewModel's `ObservableCollection<object>` (`SelectedTreeNodes`) as its own, and sets its `SelectedItem` to the collection's first item itself (`SelectionController.UpdateSelectionProperties`). Binding both would loop: in Extended mode a `SelectedItem` set from outside is *inserted* at the front of `SelectedItems` without clearing it, and from inside a `CollectionChanged` handler that throws. `SelectedTreeNode` is therefore the collection's first item, raised by the ViewModel; setting it picks that row alone, as a click does.
  - A plain click adds the new row before removing the old ones, so the first item changes only on the removal; a Ctrl+click appends, leaving the first as it was. When a leaf becomes first, `SyncTreeSelection` finds it first already and leaves the collection alone, as it must mid-change.
  - A moved row is dropped from the selection too, and with several picked the next would become first and its record picked. So `Refresh` runs flagged (`TreeSelection.Quietly`) and the rows picked are put back after (`TreeSelection.Restore`). `TreeSelection` holds this for all three: `Nodes`, `Pick`, `BringFirst` and `Restore`; each screen keeps its own `TreeSelectionChanged`, which knows what picking its leaf means.
  - Folders stay selectable: cancelling `SelectionChanging` for them would trap the arrow keys, which move by selecting the next row. A folder picked leaves the form as it is.
  - In Extended mode the tree's Home moves only the focus border, its arrow keys do nothing while `CurrentItem` is hidden by a search, and a `SelectedItem` set from outside is inserted in front (Application Architecture, the Vim keys).
- **Drag and drop**: `ItemDragOver`'s `DropPosition` only drives the indicator and cursor; `ItemDropping` works the position out again, and `Handled = true` there stops the tree moving any node itself. `DropAsChild` is offered only over a row whose type has children. A drag starts only on a move past the system drag distance while the pointer is still over the row pressed, so a script has to nudge within the row before moving away. A drag carries every row picked when the row pressed is one of them (`GetDraggingNodes`).
- **A row's right-click menu is `ItemContextMenu`, swapped per row in `ItemContextMenuOpening`** (the approach of Syncfusion's `treeview/Views/EditingDemo.xaml`). The tree opens a row's menu only while `ItemContextMenu` is non-null, so a stand-in empty one is set in XAML and `e.ContextMenu` replaced with the one built for the row (`IListTreeScreen.TreeMenuFor`, turned into `MenuItem`s by `Controls/TreeContextMenu`). The tree marks `ContextMenuOpening` handled, so its own `ContextMenu` (also a stand-in) only opens on the empty space below the rows.
  - From the menu key or Shift+F10 (`CursorLeft` and `CursorTop` both −1) the picked row's menu is opened by hand under its row: one the context-menu service opens from the keyboard is placed over the row whatever `Placement` says.
  - **A right-click doesn't select the row** (it only focuses the tree), so `ItemContextMenuOpening` picks it first unless it's among the rows picked. The menu is themed explicitly, like a dialog.
- **F2, Del and Enter reach the tree's `KeyDown`**: its own keyboard handling takes F2 only with `AllowEditing`, Delete only with `AllowDeleting`, and Enter only to end an edit, none of which is on.
- **The theme draws the tree transparent and never reads its `Background`**, so each list card puts a `Border` behind it filled with `ListBackgroundBrush`, rounded as the tree's own border (4px), to match the grids.

### `SfTreeGrid`: the Scaling tab

- **The Products screen's Scaling tab is an `SfTreeGrid`** (`ScalingCard`; in `Syncfusion.SfGrid.WPF`): read-only, nested rows (`ChildPropertyName="Children"`), every level open. `GridHeaderHeight` and `GridKeyboardFocus` are registered on it as on `SfDataGrid`: its header cell is a `TreeGridHeaderCell`, and both are `SfGridBase`s.
- **It must be themed on its own, never through the window** (`SfSkinManager.Theme` and `SizeMode` set on the `SfTreeGrid`). The Windows11Light `SfTreeGrid` dictionary merges SfGrid's unthemed `Control/Themes/Generic.xaml`, whose implicit cell, header, row and add-row styles have the keys the `SfDataGrid` dictionary themes, and `SfSkinManager` adds each control's dictionary to one root dictionary in the order it meets them, so through the window every data grid in the app lost the theme. Themed locally, the dictionaries go into the tree grid's own `Resources`. `TreeGridThemeScopeTests` also expects the inherited case to break, so it fails once Syncfusion's dictionary stops carrying the generic styles. **Any future `SfTreeGrid` needs the same local theme.**

### `SfChart`: the History tab

- **The Products History tab's Cost Over Time is an `SfChart`** (`HistoryCard`): a `CategoryAxis` of versions, a `NumericalAxis` (`N2`), a legend at the top, and a `LineSeries` each for Base Cost, Suggested Price and Current Price, sharing one `ItemsSource` (`ProductVersionHistory.Trend`) with their own `YBindingPath`, a fixed colour each through `Interior`, and point markers through `AdornmentsInfo`/`ChartAdornmentInfo`. A missing current price is `NaN`, which draws a gap.
- **Its shape**: one `PrimaryAxis` and one `SecondaryAxis` (property elements), a `Series` collection and an optional `ChartLegend`. A fixed colour per series is `Interior` on it; `Palette="Custom"` with a `ChartColorModel` colours the segments within one series, not separate series. Bind a `DateTimeAxis` to a `DateTime`, not a `DateOnly`.

### `PrintPreview`: the print pane

- **`PrintPreview` is the print pane** (`Syncfusion.Windows.Shared.Printing`, in `Syncfusion.Shared.WPF`): the Print tab's (`ProductPrintView`, on the main window) and the Price Simulator report's dialog (`PrintPreviewWindow`, an `AppWindow`). It's the print backstage SfDiagram uses: Print, Copies, the printer and its properties, the page range, collation, orientation, the printer's own paper sizes and margins on its left; the pages, page navigation and zoom on its right. No skill or Sample Browser demo drives it with content of its own, so what follows comes from decompiling it and SfDiagram's `DiagramPrintManager`.
- **It's driven by a `PrintManager` subclass** (`Printing/ProductPrintManager`).
  - `ComputePageCount` (protected virtual) lays the printout out and sets `PageCount`. `CreatePage(int, PrintPageControl)` sets the page control's `Content`; it's `protected internal`, so it's overridden as `protected override` from outside the assembly. The page control's template lays the page out with its margins, so the content fills only the printable area.
  - `InitializePrint` swaps `PageWidth` and `PageHeight` for the orientation before calling `ComputePageCount`, and the pane calls it again (`PrintPreviewPanel.InValidate`) on every change of paper, margins or orientation; `OnPrintPropertyChanged()` does the same for the subclass's own.
  - **The pane shows one page at a time** and reuses one page control as it scrolls, while printing asks again with new controls, so every call builds new visuals: an element can have only one parent. `InValidate` returns early when `PageCount` is 0, leaving the old pages, so a layout always has a page.
  - **`PrintDocument` is overridden so the job goes out on the printer's own ticket.** The base class prints on a ticket the pane builds (`GetCustomizedPrintTicket`), with a bare paper size, which Microsoft Print to PDF can't take: its filter pipeline stops and the PDF is empty. `JobTicket` takes the printer's own ticket (`UserPrintTicket ?? DefaultPrintTicket`), puts the pane's orientation, copies and collation on it with the printer's paper nearest the page, and has the printer validate it (`MergeAndValidatePrintTicket`).
  - The base class swallows every exception, so the override logs a failure and raises `PrintFailed`, which the Print tab and the dialog show in a message box. A cancel where the printer asks something, such as a PDF's file name, stays quiet.
- **The window is themed before the pane goes in**: a `PrintPreview` already in a window when `SetTheme` reaches it throws a `NullReferenceException` from `OnApplyTemplate` on its first layout. The main window is themed at startup, before the Print tab's pane is made, and `PrintPreviewWindow` themes itself in its constructor, so whoever opens it mustn't theme it again. `PrintPreviewThemeOrderTests` expects the wrong order to throw, so it fails once Syncfusion fixes it.
  - **Every test that themes a window runs on one shared STA thread, `StaThread.RunThemed`**, which also registers `App.ThemeSettings`: SfSkinManager keeps a theme's dictionaries with the thread that loaded them, and a window themed on a second thread fails ("a different thread owns it").
- **It's fitted to the app's 14px text** (`Printing/PrintPaneFit`): the theme sizes the pane for 12px. Once the pane is loaded (templates applied, before its first frame), `PrintPaneFit` changes the parts it finds by name: the settings column 250 → 340px (`OptionsWidth`), each dropdown 220 → 300px and as tall as its item, the Copies, From and To boxes, the Copies label and Print caption sized to their text, and the page box with "/ n" beside it. A part it can't find is logged and left alone. A copy of the theme's templates would lose their styles, which the app's XAML can't reach.
  - The dropdowns get item templates of their own (`Printing/PrintPaneTemplates.xaml`, loaded as a class so tests can load it): an icon and a name, with a second line where the theme has one, at least 44px tall and growing with the text. The default printer's badge is a white tick on `AccentForegroundBrush`.
  - **A ComboBox keeps the item template its choice was first shown with**: it redraws its closed box only on a new selection, a new template or a change to `IsEditable`. The printer, page range and collation are chosen while the template loads, and choosing again would reload the printer's papers, so `PrintPaneFit` switches `IsEditable` on and off again.
  - **A re-layout drew the page at 100% while the zoom read otherwise.** `InValidate` takes its page control out of the panel and puts it back within one layout pass; out of the tree it loses the theme's style, and back in it gets a new `PART_Viewbox` of no size, which the pane sizes only in `OnZoomFactorChanged`. `PrintPaneFit.KeepZoom` watches the page's `Template` (it's never unloaded, so `Loaded` doesn't fire) and, when the viewbox has no size, moves `ZoomFactor` by one and back.
  - **Neither template gives the page its paper**, so `CreatePage` sets the page control's `Background` to `PrintPaperBrush` and its `BorderThickness` to 0.
  - Covered by `PrintPaneFitTests`, on `RunThemed`: the widths, every closed box on the new item, no visible settings text cut off (measured against `LayoutInformation.GetLayoutClip`, since a block held to a smaller height keeps its text's `ActualHeight`), and the zoom kept through a re-layout.
- **The page starts as `PrintSettingsBase`'s A4 with 2.5 cm margins**, then takes the printer's paper list and default paper once the pane loads. With `GetScaleOptions` left null, the Scaling picker hides. `GetPrintDocument()` returns the pages as a `FixedDocument`, the fallback if the pane ever misbehaves: a WPF `DocumentViewer` and `PrintDialog` over the same layout. Only Microsoft Print to PDF has printed it in the app's checks.

## The toasts

- **`ErrorToast`** (`Controls/ErrorToast.xaml`) shows a screen's `ErrorMessage` in its page's bottom-right corner, 16px in, over the cards: a red error icon, "Error", the message and a close button. It never sets a `DataContext`, so a screen drops it into its root Grid, spanning every row and column. It stays until closed or until the error clears, which the next action does (`RunSafelyAsync` clears `ErrorMessage` and `SuccessMessage` first); a new error replaces it, and the same error twice shows twice. Closing it only hides it.
- **`SuccessToast`** (`Controls/SuccessToast.xaml`) shows `SuccessMessage` in the same corner, laid out alike in green with a check icon. It fades out 4 seconds after it opens, unless the mouse is over it (checked again every 4 seconds), and its close button hides it at once. Both share `ToastCloseButtonStyle`.
- **Which screens have them**: Raw Materials, Sub-Assemblies, Products, Reports and the Price Simulator have both; the Print tab and Settings' lookup tabs the error toast; Settings' Costing Defaults and Database tabs both.
- **Not Syncfusion's `SfToastNotification`**: its toasts are always-on-top pop-ups, so one left open floats over other programs, and in `Window` mode it anchors to the window's restore position, so a maximized window's toast lands too low, with no offset to correct it.

## Reports

- **`ReportsView` is one card holding a `TabControlExt`**, styled like the in-card detail tabs (a Mantle strip along the bottom, fixed tabs), each tab a read-only `SfDataGrid` that sorts on a header click, under a heading, an Export to Excel button (Application Architecture) and a one-line caption. The five tabs: Product Cost Summary, Raw Materials Price Summary, Cost Buffers, Cost Drivers and Margin Erosion.
- **Every table keeps its layout between runs**: filters, sort and hidden columns are written to the view-state file (`reports-product-costs`, `reports-raw-material-prices`, `reports-cost-buffers`, `reports-cost-drivers`, `reports-margin-erosion`) by `Controls/GridLayoutKeeping` whenever `FilterChanged`, `SortColumnsChanged` or a column's `IsHidden` changes, through `GridLayoutStore` (one line per filter predicate, its value tagged by type), and put back on the grid's `Loaded`. The rows arrive after that and the grid adds them unsorted, so the keeper refreshes the view once a batch of collection changes has landed. A line it can't read is left out. Tests: `GridLayoutStoreTests`.
- **Double-clicking a row opens its product or material** (`CellDoubleTapped`, which a header cell doesn't raise) through `OpenProductCommand`/`OpenRawMaterialCommand`, whose requests `MainWindow` opens through `ScreenNavigator.OpenOnAsync`. **The open waits until the double-click's press is over** (`Dispatcher.BeginInvoke` at `Input` priority): the grid raises the event halfway through the second press's `MouseLeftButtonDown`, and switching the main tab there takes Reports' content off the window, so the rest of the press bubbles through the content's logical parent, the Reports `TabItemExt`, which selects itself again. **Any handler that changes the main tab from inside a mouse press has to defer the change the same way.**
- **Product Cost Summary** (`ProductCostRow`): every product as saved, priced through `SavedProductReader`, so it agrees with Products and Print, one sellable unit each: Product, Stage, Category, Pieces, Ingredients Cost, Wastage Cost, Packaging Cost, Labor Cost, Overhead Cost, Admin Cost, Base Cost, Suggested Price (the Costing tab's Total Selling Price), Rounded Price (rounded up by Settings' price rounding), Current Price, Markup % (what the current price earns), Target Markup % (the Markup Metric) and Short By (how far the markup is short of it, blank when it isn't). Current Price, Markup % and Short By are blank without a current price.
  - **The headings wrap onto two lines** (the grid's `HeaderTemplate`, right-aligned, and `GridHeaderHeight.Lines="2"`), and each star column has a `MinimumWidth` that fits its widest heading word with the sort arrow beside it (the word at 14px, 11 for padding and border, 25 for `GridColumnSizer.SortIconWidth`; Category another 28 for its funnel, `FilterIconWidth`), so a word never breaks. Product (frozen, `FrozenColumnCount="1"`), Stage and Pieces have fixed widths: `ColumnSizer="Auto"` measured the empty grid before the rows arrived. A window narrower than the minimums scrolls the figures sideways under Product.
  - **Product, Stage and Category filter** from a funnel in their heading (`AllowFiltering`): `FilterPopupStyle` makes it `CheckboxFilter` only, without the pop-up's own sort, 340px wide. The theme's `CheckboxFilterControl` lays the list out in a column fixed at 188px whatever the pop-up's width, so `Controls/CheckboxFilterFill` makes it `*` when the grid raises `FilterItemsPopulated` (`CheckboxFilterFillTests`). A hidden column's filter still applies, and the filters survive the report's reload.
  - **Columns** (a `DropDownButtonAdv`) holds a tick box for every column but Product, bound to its `IsHidden` through `InverseBooleanConverter`; `ReportsView` fills the list (`ColumnChoices`) from the grid's own columns, so a new column is listed without more work.
- **Raw Materials Price Summary** (`RawMaterialPriceSummaryRow`): every purchased material, by name: Raw Material, Type, Category, Unit, Price, Change % and Since. Price, Unit and Since are the latest price-history entry; Change % is its cost per base unit against the entry before it, per base unit since the two can be in different units. Blank for a material never priced, and a blank Change % with one price. One query reads every material's history (`IRawMaterialPriceHistoryRepository.GetAllAsync`).
- **Cost Buffers** (`CostBufferRow`): every priced purchased material's buffered cost against the brand it's costed at, with **Only below target** and **Re-apply Target Buffer** (the Raw Materials notes, "The target buffer").
- **Cost Drivers** (`CostDriverAnalysis`): the purchased materials that make up most of the products in Production's material cost, one sellable unit each, at buffered costs: Raw Material, Category, Products, Cost in Products, Share %, Cumulative % (Pareto), and Largest Share % with the product it's in. Each product is priced with the material at no cost against as it is, as the Price Simulator prices a change (so a material counts however it gets into a product), but only the products the material reaches (`IngredientCostRules.ReachedBy` against `PriceSimulatorReport.MaterialIdsOf`), which keeps the load within the tab's few seconds.
- **Margin Erosion** (`MarginErosionAnalysis`): each product now against its latest version saved by the end of the day picked (an `SfDatePicker`, 30 days back to start with; `IProductVersionRepository.GetLatestAsOfAsync`, one `DISTINCT ON` read), the version priced at its costs then (`ProductVersionSnapshot.ToDetail`), listing only those with a current price then and now, with **Only dropped**. A new day reads again through `LoadLatest`.
- **The reads**: the product costs, the cost drivers and the price summary are read side by side in `Task.Run`, and every product is read together (`SavedProductReader.ReadAllAsync`, on plural repository reads), in about 15 queries however many products there are, every packaging link read once and a composite's products costed bottom-up, once each. `SavedProductReaderBulkTests` checks that ten products take as many queries as three. `ReportsViewModel` takes the version and BOM repositories as optional last constructor parameters.
- Tests: `ReportsViewModelTests`, `ReportAnalysisTests` and a `BrandPricePersistenceTests` case for `GetAllAsync`.
